# Start here

**Audience:** People evaluating Maru or entering the repository for the first
time\
**Outcome:** Know what Maru is, what is ready, how to run it, and how to make a
safe first contribution\
**Estimated time:** 45–60 minutes of reading, plus any hands-on exercise

This is the only part of the documentation intended to be read in order. The
rest of the site is organized as task and reference catalogs; open those pages
when your work needs them.

## Your five-step path

1. [Understand what Maru is](what-is-maru.md). Start with the product problem
   and the boundaries Maru deliberately keeps.
2. [Learn what works today](current-maturity.md). Read status language
   correctly before relying on a proposed or historical workflow.
3. [Run Maru locally](run-locally.md). Use a disposable PostgreSQL environment
   and synthetic data.
4. [Follow a product tour](product-tour.md). Walk through one coherent,
   fictional convention setup rather than browsing database records.
5. [Prepare a first contribution](first-contribution.md). Choose a bounded task,
   verify it locally, and use the protected pull-request workflow.

## Where to stop

- **Evaluating the idea?** Steps 1 and 2 are enough. Continue with the
  [product catalog](../product/index.md) only if the direction fits your needs.
- **Exploring the application?** Continue through step 4, then use the
  [operations catalog](../operations/index.md) for the exact runbook you need.
- **Planning to contribute?** Complete all five steps and keep the
  [build and contribution catalog](../development/index.md) nearby.
- **Looking up a symbol or historical decision?** Skip the journey and use
  [reference and history](../reference/index.md) or site search.
