Date: 2026-09-14. Refs #108 and #48; both remain open.

## Outcome and boundary

This dormant continuation of protected intake PR #118 connects separate personal
selection, typed shared-answer, own-profile, invitation/roster, seal, reopen,
exact-contribution response, submit and withdraw tasks. It reuses Applications'
existing commands and one submission version. No schema, runtime privilege,
current profile, production route, host, attendee, scheduling or publication
authority changes. Requirements PRG-002/PRG-009, IDN-014, AUD-001/AUD-003,
PRI-001 and the shared UX contract remain governed by ADRs 0082/0084/0100.

Explicit code-owned self-view fields supply minimized workflow context and exact
current frozen content. Invitees receive no answers, roster, profiles or frozen
content. Leads and accepted collaborators see only their own included frozen
profile. Scope, sole version, source lifecycle and field authority are rechecked
around bounded protected reads and HTML disclosure. Required audit must succeed;
SQL field paths are compiled in database-free tests but not natively executed.

Forms preserve original version/retry/source identity, rationale and explicit
confirmation. Acknowledgement/decline binds revision, included contributor and
own frozen-profile IDs. Submission independently binds the displayed seal ID.
Editing is inclusive at its deadline; acknowledgement/submission is exclusive at
closing; withdrawal remains independent of call/edit windows. Current recorded
responses are not offered as new decisions. Owner commands remain final locked
authorities. Results redirect to the original proposal, not child result IDs;
leaving/declining returns to independently authorized own inventory.

Typed answers reuse the shared normalizer. Addresses have labelled components;
instants require explicit offsets. Person/domain references and safe-file editing
remain truthfully unavailable pending authorized choosers under #108. No raw UUID
input stands in for those integrations. Proposed-public profile consent is never
preselected or supplied for another person. Integer configured limits and signed-
32-bit shape are enforced; HTML limits use corresponding whole numbers. A retained
out-of-range answer requires a new revision before a new seal, without rewriting
or retrospectively invalidating immutable history.
