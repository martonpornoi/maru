# Programme independent moderation workspace

Date: 2026-09-14. Parent: #48; bounded delivery within #108, not parent closure.
Base: protected PR #124, squash 95ed7b847bf942be4ffcc07438d864fdb1b53961.

## Outcome and boundaries

Applications now reserves independent moderator case discovery, exact-case
metadata, separately authorized context/answers/evidence and explicit moderate,
advance and reopen tasks. Leads, all retained collaborators and every retained
reviewer assignment are excluded before complete pagination. Source-stale/final
evidence remains independently readable without authorizing fresh writes.

The new evidence projection uses the protected owner query, additional sensitive
authority and existing readiness rule. It shows configured quorum and current
valid score count, never an average/rank. History cards label action/stage/version
and retain private rationale; already-authorized opaque actor/assignment
references remain in progressive attribution details without new Identity reads.
Evidence continuation pins the inspected case version; moved snapshots yield 409
instead of mixed history or a silently refreshed moderation form.

Every action retains strict original version/retry/rationale/confirmation, with
an explicit labelled reopening target. The existing writer alone governs fresh
quorum, independent actors, current source and OPEN/WAITLISTED reopening. Final
accepted/rejected/revision-requested cases cannot reopen. Original POSTs invoke
canonical receipt handling before private source/evidence preflight; successful
minimal receipts still require current route authority. Failed intents render
only after fresh scoped metadata admission; render-time revocation fails closed.

No schema, writer semantics, runtime privilege, profile, active route, directory,
unsafe file/reference viewer, notification or PostgreSQL policy changes. PRG-003,
PRG-006, AUD-001, QRY-005 through QRY-008, UX-029 and ADR 0085 remain authoritative.
