## Outcome and contract

contracts govern the [person-reference task](../product/page-contracts/programme-person-references.md).

production route, adoption profile or generic reference resolver is introduced.

The registered `person_reference` / `programme.person` pair names an existing
Maru person in a private answer. It grants no invitation, collaboration, hosting,
consent, proposed-public profile, attendance or unrelated-module relationship.
Other kinds/types and safe files remain separate unfinished work.

The actual lead/accepted collaborator independently reads the exact applicable
question and obtains edit authority before a known-email lookup or explicit clear.
Original proposal/call/schema versions, question, actor/tenant and retry key bind
a bounded purpose-signed identifier-only proof. Positive/empty reads are audited
before label disclosure; the contact address is never in proof, answer or audit.
Confirmation uses the exact selected account without email rediscovery or rebasing.

The existing canonical answer command remains the only writer. Retained replay
precedes fresh identity, applicability and source checks. Optional paired call and
schema fences bind new digests and are checked under existing source locks;
legacy callers omitting both retain their old digest shape. Fresh nonempty person
answers require current active/verified Identity eligibility. Clear writes None;
immutable history is never rewritten. No response failure redispatches the writer.

Personal current/current-seal viewers and exact reviewer/moderator/decider answer
viewers derive the account only from an independently authorized answer. Review
anonymity excludes reference rows in SQL before target lookup, including direct
URLs. Stage question allowlists, exact assignment/independence and additional
sensitive-field authority remain required. Complete source and current-label
comparisons withhold changed rendered bytes. Labels are not frozen contributor
names; unavailable accounts retain neutral history. Pure answer formatting does
no Identity I/O and raw reference UUIDs are not edit controls.
