## Outcome and boundaries

The dormant shared-shell task now connects labelled exact draft discovery,
complete ten-category preflight, deliberate reasoned release-warning
acknowledgement, independent approval, distinct-publisher publication, explicit
whole-release withdrawal and retained publication/withdrawal history.

Existing Scheduling commands remain the only writers. No model, migration,
runtime grant, current profile, production URL inclusion, CI policy or unrelated
owner side effect changes. The reserved isolated route verifies the full
organization/series/edition relationship. SCH-004/007/012, AUD-001 and the shared
UX contracts map to ADRs 0094/0095/0096; no accepted decision is reversed.

New owner projections have independent existing field ceilings and required
audits. Candidate discovery is complete/bounded; original approval labels are
immutable revision labels. Exact-source warning evidence is receipt-coherent,
and a displayed newest acknowledgement per finding is explicitly selected for
review rather than silently creating acknowledgements. Approval pages have exact
scope-bound older anchors; pointer history rejects missing/duplicate sequence
events instead of presenting partial history. No private owner data, foreign
calendar, actor-name directory or artifact bytes are returned by discovery.

Pointer-only observation deliberately does not require current content or artifact
validity. It lets the authorized operator select an exact withdrawal without
making unsafe content valid or available. It never replaces checked output
readers. Canonical commands still enforce authorship/copy/restore independence,
distinct publication, complete source capture, warning eligibility, artifact
validation, native invariants and atomic pointer changes.

Read pages discard their complete prepared response if repeated owner sources or
field/scope admission fail after rendering. Original command POSTs instead reach
canonical receipt recovery before fresh private reads; new-intent lifecycle
checks must not preempt recovery of an already committed command. Stale/unknown
completion keeps exact versions, source, rationale and retry key. Confirmed
minimal receipts do not depend on optional current-source/navigation reads.
Final action revocation withholds output without pretending a commit rolled back.

Native forms require reason, explicit confirmation, strict bounded input and CSRF.
Responses are escaped/no-store with sensitive POST masking. The optional browser
guard retains original input and confirms discarding another action's unsaved
reason; it does not save input in a session, URL or browser store.
