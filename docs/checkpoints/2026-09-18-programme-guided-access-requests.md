# Guided Programme operational request creation

## Outcome and boundary

This increment continues the existing accountable-setup item in #108 under #48,
following protected [PR #160](https://github.com/martonpornoi/maru/pull/160).
It implements reserved shared-shell request creation beside the exact-scope approval
inventory. A current ordinary persistent controller selects one exact admitted task,
supplies two known addresses, previews exact people/scope/capabilities/UTC interval,
then explicitly submits a request through the existing Authorization owner command.
The resulting receipt still requires the named independent approver's own decision.

The original-purpose signature binds authenticated author, complete Programme/actual
target scope, recipe contents, exact people, original selectors, interval, rationale
and retry key. Confirmation and refresh never resolve mutable addresses again.
Missing selected people are not replaced; the existing command decides whether an
original retry or a fresh request is currently permitted. A successful submission
redirects before any render/read repetition. Sensitive reads are audited, including
empty matches, without retaining emails in audit, proof payloads or URLs.

Department, Edition, shared Organization Venue and exact selected-room authority
remain distinct. Multi-scope on-site recipes are filtered by each allowed level,
not accidentally excluded because their room variant declares a resource kind.
There is no new catch-all role, invitation, message, grant, schema, migration,
runtime privilege, production route or profile activation. ADR 0106 is unchanged.

Requirements: IDN-002/004/005/012/014, EVT-006/007, AUD-001, UX-005 through UX-008,
UX-019/020/027/029 and NFR-013. Authorization owns both adapter and public query;
Identity supplies exact known-address selection and minimized display labels.
