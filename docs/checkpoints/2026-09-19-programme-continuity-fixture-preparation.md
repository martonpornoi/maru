## Prepared journey

An explicit launcher option provisions a fresh scope-bound Ed25519 key after actual
setup, with a five-minute pack lifetime and key validity bounded by the original
fixture lease. Only the owned web child receives its private policy. The parent
retains independent public trust, not trust supplied by downloaded data; workers
and transition children have no private key. Secret-bearing handles hide bytes
from repr. No environment or machine-trust mutation is made.

The existing single full native journey maintains six actual HTTPS downloads:
anonymous public, exact host and volunteer, exact room and planner Department and
edition with explicit staffing. Closed route selection, signature/trust/scope,
purpose-specific release observation, complete source-row membership and private-data ceilings
precede offline use. Actual login/logout consumes the existing verified TLS/CSRF
session helper. A volunteer-only purpose retains work without observing unrelated
hosting/publication state. The lighter P01 variants retain the missing-key 503 refusal.

Each purpose uses a newly owned temporary directory and initializes history once.
The actual CLI runs in an isolated interpreter without database settings, with
socket operations and Django imports denied. It produces dated historical HTML,
not a live offline application. Repeated use preserves history; tampered data,
wrong edition, missing history and known older packs fail without an output file.
Explicit library-clock checks cover expiry and a time before issuance without
changing system time. Synthetic temporary files are removed on context exit;
this is neither secure physical erasure nor approval of device storage/custody.

Actual Scheduling withdrawal advances the observed pointer from two to three.
Fresh independent ten-source review and separate publication after reconnection
advance it to four. Stale versions are rejected, exact retries retain their
receipts, prior approvals cannot be reused and own retained work stays unchanged.
The native case independently checks SQL pointer/withdrawal/authors, current and
cancelled work history, and no Participation. No extra expensive native fixture
is added and no direct model mutation replaces an owning command.
