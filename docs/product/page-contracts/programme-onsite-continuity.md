## Audience, purpose and placement

Give public readers, genuine hosts/volunteers and independently authorized
room/Department/edition operators a useful current/next view, full run sheet,
print fallback and bounded signed snapshot from the same owning projections.
Use the existing shared public, My Maru and Administration shells respectively.
The synthetic-only route family is:

- `/programme/<organization>/<edition>/now/`;
- `/my/<organization>/<edition>/programme-now/`; and
- `/admin/programme/now/<organization>/<edition>/<room|department|edition>/<target>/`.

The exact `scheduling.programme-continuity@1` adapter and all source-owner
adapters/capabilities are independently required. A visible link, file, source
identifier, URL, signature or prior permission grants no authority. No current
profile includes these routes or the adapter.

## Data and timing meaning

Public output includes only exact released copy, effective intervals and current
public Venue wayfinding. Personal output uses the actual authenticated person:
approved required host presence and independently retained own Shift intervals.
Operator output uses its exact current scope and explicitly requested technical,
accessibility, media and staffing ceilings. No review rationale, host directory,
private availability, contacts or unrequested layer is introduced.

Current instructions have their own source versions; release publication time
and last source check are different. A hosting envelope is context, not assignment
of every phase. Tentative claims are not confirmed work; completed or removed
history is never classified as work happening now. Current demand location or
instructions never retime or relocate retained accepted work. Operator staffing
counts do not prove current qualification, availability, attendance or actual work.

Now uses `start <= observation < end`; next contains the earliest following
start, including ties. Operator entries expose preparation, delivery and teardown
explicitly, while public entries use only effective intervals. Display local
time with the edition IANA zone and offset; preserve UTC source instants and
overnight service-day identity. No browser-machine zone substitutes for the
edition zone. Full chronological entries remain reachable below now/next.

## Interaction and transitions

Lead with release/source status, current work and next work. Follow with the
complete run sheet and independently requested layer controls, then continuity
downloads and source/expiry detail. One page H1, the host's one main landmark,
ordinary labelled forms/links, visible focus and a computed Access disclosure
remain mandatory. Optional controls request fields, not grants. Refresh performs
a new complete owner read. No editor, publication or acknowledgement mutation
is hidden in a filter, timer, print or download action.

Offer native print and signed-snapshot download. Key configuration being absent
must be explicit: fresh authorized online content may still work, while signed
issuance is unavailable. A downloaded/printed copy always says when its source
was checked and when it must be replaced/disposed of. Download is neither manual
handoff nor acknowledgement; link to the existing #104 notice journey, which
authorizes independently and retains exact-version decisions.

All online formats are private/no-store where appropriate and never use an
implicit last-good fallback. Public output adds no visitor account or activity
audit. Private issuance retains the actual actor's required sensitive-read audit.
Closed inputs reject extra subjects, substituted scope, duplicate parameters,
unknown formats, unrequested private fields and malformed identifiers.

## Offline operator boundary

Provision the offline verifier and independently trusted public key/scope before
the outage. Use protected encrypted event storage and an accountable owner for
private files and paper. Signature verification authenticates the exact snapshot
bytes, not an arbitrary HTML/PDF copy, current permission or the absence of a newer
release. Do not load a key from the snapshot itself or fetch a key URL supplied by
it. No browser storage cache or mutation relay is installed by this journey.

The verifier must apply its protected latest-known signed metadata before normal
rendering, retain the highest observed release pointer through purpose loss, and
persist newer known state before releasing the rendered result. Initialization is
an explicit connected/pre-outage procedure, not an automatic response to missing
or corrupted history. Known withdrawn/invalidated state prevents re-rendering an
older ordinary pack; display withdrawn/relocation-pending guidance instead.

Any offline rendering is explicitly historical/degraded with verification time,
source age, expiry and the limitation that disconnected devices cannot know new
revocation or source changes. Existing rendered/printed copies cannot be remotely
erased: replace/dispose of them when a newer overlay is known. Never describe
previously generated HTML or paper as a live verifier. Expired/untrusted input or
unavailable known history produces no normal timetable. Retained volunteer work
is not thereby cancelled; the operator must obtain current instructions and use
the existing governed notice/recovery process.

## States and recovery

- Empty authorized scope: say no relevant rows; do not infer edition-wide absence.
- Release absent: explicit unpublished state, distinct from an unobserved personal
  release or unadopted layer; disclose no private labels without owning purpose.
- Available: now/next plus the complete correctly scoped run sheet.
- Unrequested/unadopted layer: explain the difference; never silently remove a
  requested denied or unavailable layer from a supposedly complete pack.
- Known withdrawal/invalidation: no ordinary Programme geometry, explicit warning,
  source version and recovery continuation; retained work is not silently changed.
- Invalid input: actionable labelled validation without repeating arbitrary keys.
- Denied/foreign context: non-disclosing not-available response before input lookup.
- Incomplete/moving/oversized evidence or audit failure: unavailable, no partial
  package, stale content, hidden counts or fabricated success.
- Bad signature, unknown key, scope mismatch, future clock, expiry, older known
  state or contradictory equal-time evidence: refuse normal offline material.
- Reconnected: obtain a complete freshly authorized replacement, advance known
  state and dispose of superseded copies before ordinary use resumes.
