## Meaning

A `domain_reference` question with kind `programme.call-track` or
`programme.call-format` names an additional private entry from this proposal's
own call catalog. For example, a call may ask which other track could suit a talk.
This does not change the lead-owned selection, duration, routing, Programme item,
host relationship, timetable, public copy or any unrelated module.

Applications owns these closed catalogs and the existing append-only answer.
No caller-supplied model, cross-call lookup, global directory, raw identifier entry
or URL resolution is supported. Unknown historical kinds remain unavailable and
require deliberate supported configuration; matching codes or successor calls are
never substituted. Active call configuration is immutable under its existing
definition lock and native guard. Labels describe that source, not live global data.

Response failure never redispatches a writer. No new aggregate or receipt exists.

## Exact-answer viewers

Personal current and current-seal viewers derive the target from their independently
authorized answer; frozen readers must be genuine included contributors. Reviewer,
moderator and decider viewers retain current exact seal, own assignment when required,
stage question allowlist, field ceiling and extra sensitive-content authority.
Canonical anonymous exclusions happen before any domain-target lookup, including
direct URLs. Call-management or visible-link authority does not grant answer access.

Resolve only the authorized answer's same-call code/label/guidance. Empty and
unavailable states are honest; malformed or cross-call references fail closed.
No arbitrary historical identifier can probe another call. Pure answer formatting
performs no owner I/O. Compare complete admitted source and selected target before
and after rendering; withhold changed bytes instead of a partial stale response.
Return navigation independently authorizes its destination.
