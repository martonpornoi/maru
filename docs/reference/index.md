# Reference & history

**Audience:** Contributors and maintainers looking up an exact contract,
project state, or historical record\
**Outcome:** Reach comprehensive material without placing archives in the
newcomer navigation\
**Reading time:** 2 minutes to choose a catalog

Reference material is designed to be searched and opened when a task needs it.
It is not a sequential learning path.

- [Module catalog](../modules/index.md) describes ownership, public commands,
  queries, events, permissions, and operational boundaries.
- {doc}`Python API reference <../autoapi/maru/index>` is generated statically
  from production source and tooling docstrings.
- [Project records](../project/index.md) contain current state, roadmap,
  requirements-adjacent plans, and detailed delivery ledgers.
- [Research catalog](../research/index.md) preserves reviewed product and
  operating-model inputs without making them implementation authority.
- [Checkpoint archive](../checkpoints/index.md) contains append-only milestone
  evidence for resuming historical work.
- [Architecture decisions](../architecture/decisions/index.md) explain durable
  choices and supersession history.

For a first visit, return to [Start here](../start-here/index.md). For current
behavior, prefer [what works today](../start-here/current-maturity.md) over a
dated checkpoint.
