# ADR 0134: Bound AI-assisted work and match local documentation checks to CI

- Status: Accepted
- Date: 2026-11-11
- Requirements: NFR-001, NFR-002, NFR-003, NFR-011
- Extends: ADR 0079 and ADR 0090 for routine task authority, evidence handling
  and local prose-only certification.

## Context

The maintainer approved four workflow improvements after an agent completed
the fictional Workforce guide in a fresh browser fixture. Human-acceptance
rules had been applied to ordinary software checks. Temporary one-shot
checker instructions also added repeated analysis work. The hosted
documentation plan already avoided PostgreSQL, while the required local
command still launched its database pool for the same prose changes.

## Decision

1. Identify the actual checkout and baseline before following a handoff.
   Preserve unrelated worktrees. Carry authorization for ordinary repairs,
   verification and cleanup through the approved outcome. New consequential
   scope, real consent and tool-required handoffs retain their own authority.
2. Permit agent-operated software rehearsals in fresh, dedicated fictional
   fixtures. Prepared sign-ins may be used for normal role switching and
   in-app actions. The Workforce launcher supplies an explicit mode using
   the normal invitation commands and restricted runtime. Browser credential
   setup, representative people, two-human acceptance and production approval
   retain separate evidence.
3. Preserve original run results and failures. Read-only verification code
   can be reused or corrected with identifiable versions and new outputs.
   Keep the exact input scope and any applicable sealed-evidence restrictions.
   Real setup and mutation remain tied to the owned fixture.
4. Under the required PostgreSQL policy, Auto may use a local documentation
   path when the shared hosted classifier selects that scope and the exact
   ancestor-to-head tree diff is limited to permitted regular prose additions
   and edits. The path uses the hosted static, licensing, packaging when
   selected, and fresh documentation checks. It keeps a distinct receipt and
   never replaces or deletes prior native receipts.
5. Keep the ordinary and exhaustive PostgreSQL routes, combined coverage,
   timing, security and protected delivery gates. No workflow, ruleset,
   deployment authority or production-data policy changes. Local receipts
   remain contributor evidence; GitHub evaluates its selected checks
   independently.

## Consequences

Routine fictional software testing and prose checks need fewer handoffs and
resources. The local documentation path deliberately rejects ambiguous,
destructive and mixed diffs. It does not become a general exception for
tooling or policy implementation. The implementation of this path is a
test-harness change and requires the ordinary exhaustive delivery evidence.

Roll back the local selection change to restore the previous certification
path if needed. The prepared-sign-in mode can be omitted; the default
blank-start journey and its credential checks remain available. No database
migration or production behavior changes.
